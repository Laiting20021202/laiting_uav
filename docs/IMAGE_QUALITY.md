# Jetson 辨識與目標紀錄畫質

2026-10-09 檢查確認：YOLO 使用相機解碼後的 BGR 影格；GUI 的縮圖與 JPEG 壓縮發生在辨識及目標紀錄之後。GUI 畫質設定不會壓縮辨識輸入，但相機本身的 RTSP 編碼會在影格抵達 Jetson 前損失細節。

## 各階段畫質

| 階段 | 處理方式 |
| --- | --- |
| 相機 → Jetson | 1080p RTSP；固定次串流 2 Mbps；原本設定檔為 1 Mbps |
| Jetson 解碼 | 原生 1920×1080、BGR24、4 FPS 取樣輸出；不做 JPEG 中轉，不放大或縮小來源 |
| YOLO v5 辨識 | 接收上述原始解碼影格；模型依 registry 使用 `imgsz=1280`，再做模型正常的縮放、補邊及通道轉換 |
| 本機目標紀錄 | 同一原始解碼影格，完整視野加框與下方資訊；JPG 品質 95、4:4:4，不縮小相機區域 |
| GUI 即時預覽 | 辨識後另取副本，縮到 960px、JPG 品質 55、最高 2 FPS；網頁可選 2／1 FPS |
| GUI 紀錄列表 | 最長邊 480px、JPG 品質 78；點圖片或「下載 JPG」才取得完整紀錄 |

相機每次新建 FFmpeg session 前都確認實際串流尺寸。尺寸與 `camera.width/height` 不符時顯示 `CameraResolutionMismatch` 並重試，避免將 720p 放大為 1080p 後誤認為清晰來源，也避免 rawvideo 尺寸錯位。畫面比例不符仍顯示 `CameraAspectRatioMismatch`。

## 碼率與穩定

相機重新連接後實際回讀為 `SecStream_BitRate=2M`；選項為 `5M, 4M, 3M, 2M, 1.5M, 1M, 0.5M, 0.2M, 0.1M`。依使用者後續要求以穩定優先，設定固定為 `2M`，不自動升到最高 5 Mbps。1080p/30、EIS 關閉、240 秒 session 更新及既有故障重連策略保留。

2026-10-10 依約 200 ms 推論時間，將先前的 20 FPS 改為 4 FPS 取樣輸出，每幀 250 ms；推論、紀錄與預覽編碼均計入處理時間，每輪至少休息 50 ms。較慢時只處理下一張最新影格，不追趕舊影格。GUI 編碼及預設抓圖降為 2 FPS，以減少負載與外網影像傳輸量；來源解析度、模型輸入尺寸與紀錄畫質沿用原設定。FFmpeg 仍須解碼相機端的 30 FPS 壓縮串流，4 FPS 是輸出給 Python／模型的取樣率。

2 Mbps 是本次畫質與負載的折衷，不能保證小目標細節與訓練圖片相同，也不能用短期連線成功宣稱 H2 長時間凍結問題已解決。既有紀錄中的壓縮損失無法由提高新紀錄 JPG 品質恢復。

## 與訓練驗證的差別

`president-cup-v5` 的訓練使用 `imgsz=1536`，實機 registry 現在依 realtime demo 對齊需求使用 `imgsz=1280`。這是模型輸入尺寸；即使收到 1920×1080 原圖，YOLO 仍會做正常前處理。它與 GUI 的 960px JPG 是兩條獨立流程。

信心門檻由使用者在 GUI 調整；後續依要求將預設新目標門檻對齊 45%，續追 10%，漏檢保留 0.35 秒，見 [辨識與追蹤設定](DETECTION_TRACKING.md)。先前 `models/president_cup_v5/evaluation/fixed_threshold_comparison.json` 的比較使用 25%、30%、45%，NMS IoU 0.60、最多 300 框；實機程式目前 NMS IoU 0.55、最多 100 框，Jetson GPU 使用 FP16。上述條件及真實場景、目標像素大小、曝光、對焦與運動模糊，都可能使實機輸出與訓練驗證不同。原始模型信心及保留框都不能當成準確率。

## 驗證方式

回歸測試使用含單像素彩色細節的無損 FFV1 影片，確認解碼後逐像素一致，並拒絕來源解析度不足。另一項測試把 GUI 壓到 160px／品質 10，確認 Runtime → Detector → 模型及紀錄仍收到同一張 1920×1080 影格，原始像素未被預覽標記或壓縮修改。紀錄測試同時確認完整尺寸、4:4:4、框與資訊保留。

先前 15:15 部署的 1536／10 FPS 版本有 76 項相關測試通過。當時相機連接後在 Jetson GPU 進行單影格實測，確認原始解碼影格為 `1080×1920×3`，實際 YOLO 接收同一個陣列且前後像素雜湊一致；模型前處理產生 `1×3×864×1536` 的 FP16 tensor，預覽另縮為 `540×960×3`。回讀碼率為 2 Mbps。服務套用後恢復相機及飛控，新目標紀錄讀回完整 1920px、4:4:4 JPG。這是先前版本的輸入流程驗證，沒有量測辨識準確率或長期穩定性；後續 1280／20 FPS 與追蹤測試另見 [辨識與追蹤](DETECTION_TRACKING.md)。
