## 哪些問題仍未解決

1. **原始 USB transaction failure 尚未根治。** 該次開機 identity 已確認使用 xHCI short-transfer 修補核心及 `laiting-usbnet-1.0`，仍出現凍結。這些回補不能宣稱已解決全部故障。
2. **恢復流程有可修正的缺口。** rebind 失敗後 USB 存在但 CDC 未綁定，流程卻回到一般等待／無效 NM reconnect；USB reset 又沒有明確重新綁定 CDC。這解釋第二段為何延長。
3. 尚不能單憑 transaction error 或 `-71`，確定缺陷只在 D-Link 韌體、Jetson 控制器或實際 USB 通道中的哪一方。[Linux 官方錯誤碼說明](https://docs.kernel.org/driver-api/usb/error-codes.html) 指出 EPROTO 可代表無回應、協定或其他無法細分的 USB 錯誤。

17:13–17:19 飛控 serial 仍在、沒有对应的應用心跳失聯紀錄；不能把這次網卡失效直接歸為飛控同時故障。板端 VIN 約 20.0 V、過流及電流警報為 0，但沒有直接量測故障瞬間的 USB 5 V，這不構成排除全部瞬間供電問題的證據。
